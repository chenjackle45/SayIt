# 計畫：AI 整理時說明字典清單的用途（#84 續，跨平台）（v0.15）

> 建立：2026-11-18 · 狀態：**已實作、實作閘 R1 可提交**（計劃閘 R1 GO 附條件；真模型實測後使用者拍板出貨 strong2）
> 來源：#84（ian90041）11/17 回覆 v0.14.2 後仍「還是一樣」：手動加的人名 Anny、Ariya 每次都變成 Annie、Area；AI 整理有開（模型未答、截圖經 email 遺失）。拍板：2026-11-18 使用者同意「#84 修正排進 v0.15、現在開工」。
> 前一卡：`docs/plan-vocabulary-manual-priority.md`（v0.14.2：手動詞優先送出）——那張解決「詞有沒有送出去」，本張處理「送出去之後 AI 知不知道要拿來做什麼」。

## 要解決什麼

| | 已查證的事實（讀碼） | 推論（待驗） |
|---|---|---|
| 附加方式 | `buildSystemPrompt`（`src/lib/enhancer.ts`）在指示**尾端**附 `<vocabulary>\nA, B, C\n</vocabulary>`，沒有任何說明文字 | — |
| 指示內容 | 內建指示（`src/i18n/prompts.ts`，五語系＋粵語、精簡／積極兩模式、自動語言版）**全部沒有提到這個清單**；精簡版有「不確定就不改」、舊版有「如果不確定…保留原文」 | 模型看到一串沒說明的詞，加上「不確定就保留」，傾向維持 Annie 不改成 Anny |
| 語音辨識 | Whisper 端另有「Important Vocabulary: …」提示（`transcription.rs`），只能提高機率、不能強制 | Anny／Annie 發音相同，Whisper 多半輸出常見拼法；修正只能靠 AI 整理這一步 |
| 指示語言 | 內建指示的語言由 `getAiPrompt()` 決定（明確辨識語言→該語言；「自動」→介面語言版的自動語言指示；自訂指示→使用者自己寫的）。`buildSystemPrompt` 不知道指示是哪個語言 | 說明句若與指示本體語言不同，可能影響輸出語言（#83 教訓：模型跟著指示本體的語言走） |
| 編輯模式 | 編輯模式的指示也走 `buildSystemPrompt`，但**不帶字典**（只傳一個參數） | 本卡不影響編輯模式 |
| 短句略過 | 使用者設定「低於 N 字不整理」開啟時，短句直接跳過 AI 整理（`useVoiceFlowStore.ts` 即時整理入口） | 回報者若只講一個名字且開了此設定，本修正不會作用——回覆時一併問 |

## 方案

在 `<vocabulary>` 區塊**前**加一句說明，語言與指示本體一致：

- zh-TW 草稿（計劃閘 R1 改窄）：「以下是使用者字典的偏好寫法。校對疑似人名或專有名詞辨識錯誤時，優先採用發音相符的字典詞；若上下文明確是其他詞或另一個名字，保留原文。其餘內容與輸出語言遵循原規則。」——不再寫「一律改」與「優先於不確定就不改」
- 其他語系（en、ja、zh-CN、ko、粵語用 zh-TW 句）語意相同；ja／ko 由 zh-TW 語意翻譯

說明句的語言：由呼叫端傳入「指示語言」——內建指示用 `getAiPrompt()` 當下選中的那個語言（明確辨識語言→該語言；自動→介面語言）；**自訂指示用介面語言當後備**（無法得知使用者寫的語言；**不保證**與自訂指示本體同語言，跨語言影響由驗收 5 的自訂跨語言案例實測）。實作上在 `EnhanceOptions` 加一個指示語言欄位，`buildSystemPrompt` 依它挑說明句；設定 store 補一個回傳「目前指示語言」的函式，三處呼叫點（即時整理、HUD 重試、歷史重整理）一起帶上。

## 不做

- 不改 Whisper 端的提示（只能提示、改了也不保證，且動 Rust）
- 不做「名字對應表」（Annie→Anny 的強制取代）：會誤傷真的叫 Annie 的情況，且需要新 UI
- 不改 50 個名額、不改排序（上一卡已處理）
- 不改編輯模式

## 改動檔案（預估）

- `src/i18n/prompts.ts`：新增各語系說明句與取用函式
- `src/lib/enhancer.ts`：`EnhanceOptions` 加指示語言、`buildSystemPrompt` 在清單前加說明句
- `src/stores/useSettingsStore.ts`：回傳目前指示語言
- `src/stores/useVoiceFlowStore.ts`、`src/stores/useHistoryStore.ts`：三處呼叫點帶指示語言
- 測試：`buildSystemPrompt` 各語系、無字典時不加說明句、自訂指示走介面語言

## 計劃閘 R1（2026-11-18，codex gpt-6.1-sol xhigh 唯讀、審查暫存區）

判定 **GO 附條件、0 HIGH**；出貨前需確認收益與誤改風險。查證：清單附在尾端無說明、最多 50 詞；兩模式五語系＋粵語＋自動版皆未解釋字典（精簡版有「不確定就不改」、積極版沒有）；三個整理入口都帶字典、編輯模式與連線測試不帶；「Whisper 多半輸出常見拼法」仍屬推論。

| 等級 | 問題 | 處置 |
|---|---|---|
| MED | 「發音或拼法相近一律改」會誤改語意正確的普通詞與真實姓名，現有檢查攔不到 | 收：說明句改窄（疑似人名／專有名詞、上下文明確是別的詞就保留）；控制句加 area、Annie Lennox |
| MED | 自訂指示用介面語言只是後備，不等於與指示本體一致 | 收：改寫保證範圍；驗收 5 加自訂跨語言兩例 |
| MED | 六句正例、無重複與門檻，不足判定出貨；漏算退回原文；未涵蓋 #83 敏感型號 | 收：驗收 4 改固定樣本＋控制句＋每格 3 次＋計分方式；驗收 5 定門檻；加 gpt-5.6-luna 語言回歸 |
| 規格建議 | 「優先於不確定就不改」無單獨驗收證明必要 | 採納：從說明句拿掉，先用窄措辭實測 |

三問結論：生產者明確（Whisper 近音名＋使用者字典）；會進入作用路徑但效果待實測；**短句略過整理開啟時單講名字不會作用**；單獨的 Annie 無法證明原意，字典只能提供偏好。

## 真模型實測（2026-11-18，驗收 4、5）

條件：zh-TW 指示、字典 50 詞（Anny、Ariya＋48 固定填充詞）、6 正例＋6 對照句、每格 3 次；呼叫走 App 的請求組裝、長度爆炸重試、語意飄移守衛與繁簡轉換（「成功」＝最終被接受且內容正確）。共 1,200 次呼叫，連線錯誤 2 次（qwen 503，計入分母）。腳本與原始結果在 job tmp `vocab84/`（不進 repo）。
