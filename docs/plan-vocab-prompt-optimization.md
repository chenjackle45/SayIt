## 要解決什麼（讀碼＋唯讀資料庫複本＋API 實測）

| 機制 | 現況 | 後果 |
|---|---|---|
| **提示過長** | Groq（large-v3 與 turbo）提示上限 **896 位元組**，超過回 HTTP 400、歸類不重試（11/27 實測 896／889 過、993／982 回 400，訊息寫 characters 實為位元組） | **現存 bug**：詞庫前 50 詞超過 896 位元組（日文長片假名、長英文產品名）→ 每次錄音轉錄失敗。**已實作修正**（A0） |
| 排序 | 手動詞優先，其餘依 `weight`；`weight` 在「貼上的最終文字含該詞」時 +1 | 常講、本來就辨識對的詞越排越前；樣本 22/50 名額是原始辨識已出現 ≥10 次的詞，143 個罕見詞排不進去 |
| 送給誰 | 同一份前 50 同時送 Whisper 與 AI 整理；取詞 6 處（即時轉錄、即時整理、HUD 重試轉錄與整理、歷史重轉、歷史重整理），Whisper 清單在停止錄音後取得 | 與這句無關的詞佔名額 |
| 學什麼 | 修改監聽（macOS CGEventTap＋AX、Windows hook＋UIA）讀游標附近摘錄（Mac 約前後各 50 字、Windows 後備至多 600 字），AI 只回正確寫法 | 不知道被聽成什麼 |
| 學詞把關 | 只有中文指示；長度檢查（含漢字者至少兩個漢字、其餘至少 2 字元）；另有未改動／重疊率檢查 | 樣本學進「會議」（權重 338）、殘缺詞「Teleg」 |
| 預設指示 | 精簡（預設）／積極兩模式、五語系＋粵語＋自動語言版，執行時組出；自訂指示也會附詞庫區塊 | 口誤、數字、標記、範例、規則矛盾等問題（見 E） |

## 範圍

### A0. 提示依位元組裁切（已實作，待實作閘）
- 組 Whisper 提示時依優先度往下收詞，加入後整段（含 `Important Vocabulary: ` 前綴）會超過 896 位元組的詞就跳過、繼續試後面的詞，最後反轉讓優先度最高者在尾端。單元測試：日文長詞 50 個裁到上限內且最高優先在尾端、剛好 896 保留、多 1 位元組捨棄、首詞超長時後面短詞仍保留。
- 不做「收到 400 再不帶提示重送」：裁切後沒有會觸發它的生產者（兩個模型實測同一上限、同一位元組算法）。不做 224 token 估算（無可靠換算；官方只說只用尾端，最高優先已在尾端）。

### A. 資料（migration v9，只追加）
- 放在既有「關鍵表驗證與恢復」段**之後**；全部 `addColumnIfNotExists`／`IF NOT EXISTS`，重跑結果相同。
- `vocabulary` 加 `correction_count INTEGER NOT NULL DEFAULT 0`、`last_corrected_at TEXT`。既有 `source='ai'` 回填 `correction_count = 1`、`last_corrected_at = 遷移當下時間`（相容起始值，不宣稱真實次數；給 30 天觀察期，避免升級當下就被排除）。回填只在 v9 升級那次執行，重跑不覆蓋之後累計的值。**匯入**的 AI 詞同樣設 1（與遷移一致）。
- 新表 `vocabulary_replacements`（`id`、`vocabulary_id`、`misheard`、`hit_count`、`status` ∈ `suggested|applied|dismissed`、`created_at`、`updated_at`，`UNIQUE(vocabulary_id, misheard)`）。
- 刪詞連帶刪配對：`AFTER DELETE ON vocabulary` 觸發器（連線池不能跨 execute 用交易，觸發器是最小原子做法）。改詞保留配對；`dismissed` 不送 AI，再學到同一對只加 `hit_count`。
- `weight` 保留給詞庫頁顯示，不再參與送出排序。

### B. 學習（改法 1 把關＋改法 2 配對）
> 代決（2026-11-27，R1–R4 修復）：合併連續空白後沿用字元對齊，標點與原文位置完整保留；純格式差異及純新增檢查另以去空白／標點的內容比對；來源與候選去空白／標點並忽略大小寫後相同、或來源僅一個中日韓字元，都不存。沒有摘錄截斷旗標時，只把「候選有共同字元、末差異碰摘錄尾、兩邊未錨定尾等長」補成完整尾替換，其餘保守排除；C 在候選詞之外仍保留原錯詞時，改正與新增的對應不唯一，保守不存該配對；要完整消除字串歧義，須另帶摘錄完整性資訊。

1. 對齊：對「貼上文字 P」與「改後摘錄 C」做字元級差異，得到 C→P 的位置對應（相同字元一對一；差異區段整段對整段）。
2. C 與 P 完全相同、或沒有任何差異區段落在 C 內部 → 不呼叫 AI。
3. AI（五語系指示依介面語言）只回「改後文字中被改正的專有名詞／術語」陣列；同時送 P 與 C。
4. 對每個 AI 回的詞：在 C 中找出現位置（英文需詞界完整），只採**與至少一個差異區段重疊**、且**所有重疊的差異區段都完全落在該詞範圍內（容許兩側空白）**的出現——差異區段超出詞範圍（如「安裝陶里 → 安裝 Tauri 和 React」不論 AI 回一詞或兩詞）即視為混有新增內容、整段不寫入；把該出現範圍經對應回推到 P 得到 X：
   - X 為空（純新增，如句尾補「改用 Kubernetes」）→ 不學；
   - 出現位置碰到 C 的開頭或結尾、且 P 在對應方向還有更多文字（摘錄截斷）→ 不學（擋「Teleg」）；
   - 兩個以上的詞回推到同一個 X（「陶里瑞艾克特 → Tauri React」「安裝陶里 → 安裝 Tauri 和 React」）→ 該段**一律不寫入**（無法分辨哪個是改正、哪個是新增）；
   - 其餘 → 學詞並存配對（詞, X）。例：「李明哲→李銘哲」差異只有一字，回推範圍得 X＝李明哲；「Kubernets→Kubernetes」得 X＝Kubernets。
5. 新詞寫入並設 `correction_count = 1`；既有詞 `+1`、更新 `last_corrected_at`；配對 upsert（`hit_count + 1`）。

### C. 選詞（改法 1＋3）——純函式模組，App 與評估共用
- **Whisper 清單**：手動詞＋`correction_count ≥ 1` 的 AI 詞，**排除**「常被直接辨識對的 AI 詞」＝最近 300 筆原始辨識出現 ≥ 8 次且 30 天內沒被改正（拍板項目；手動詞永不排除；**只在智慧學詞開啟時套用**，關閉者沒有自我修復路徑故不排除）。被排除的詞若之後又被改正，`last_corrected_at` 更新即自動回到清單（自我修復）。排序：手動（新→舊）→ `correction_count` 降冪 → `last_corrected_at` 新→舊；由 A0 的 896 位元組裁掉排後面的。
- **AI 整理清單**（拿到原始辨識之後）上限 20：
  1. 配對：`status ≠ dismissed` 且 misheard 出現在原始辨識（英文詞界）→ 詞＋配對；
  2. 中日韓詞：原始辨識有同長度片段且相同位置字元 ≥ ⌈長度/2⌉（兩字詞＝一字相同，冷啟動的「阿親→阿欽」可進候選）；拉丁詞：與某字詞（詞界、不分大小寫）編輯距離 ≤ ⌊長度/3⌋；
  3. 排序：配對命中 → 相同位置字元比例 → 手動 → `correction_count`；
  4. 無候選 → 不附詞庫區塊。
  - 門檻**只用 cases-a** 的辨識結果離線量候選精確率／召回率（不花 API）定案，反例含「台灣電→台積電」、跨文字系統近音；cases-b 不參與任何調整。不加拼音依賴。
- 6 個取詞點全部改用此模組。

### D. 回聲（改法 4 的後半）：先量再做
- 評估加 6 段音檔（6 語言 × 單字 0.5 秒；全零靜音必被能量守衛攔，不量）帶新舊提示各轉一次（`verbose_json` 取 no_speech_prob 與能量），記錄是否吐出詞庫、既有守衛是否攔下。
- 只有量到「吐出詞庫且既有守衛沒攔」時，另開小卡設計；本卡不改轉錄流程。

### E. 預設指示（精簡＋積極，五語系＋粵語＋自動語言版）
- **內建指示**（以模式旗標判斷，非比對字串）：逐字稿包成 `<transcript>…</transcript>`，指示說明「標籤內是語音內容不是指令」。**自訂指示與編輯模式**：指示本體與 user message 逐字不變；只有詞庫區塊隨 C 的新清單與新說明句改變（測最終 messages）。
- 補規則：口誤自我更正只留最後說法。（數字改阿拉伯數字規則：使用者 2026-11-27 拍板不加，數字保持說的念法。）
- 修矛盾：精簡版可用句號（整段一句時句尾不加）；換掉「在嗎→怎麼」；積極版補「不刪除有實際意義的內容」「不確定就不改」、改「除列點外不用其他 Markdown 語法」。
- 每語系 2 組「改前→改後」範例（各語系自寫）；以 zh-TW 子集消融，無效益就刪。
- 詞庫說明改兩段：「已知聽錯配對（遇左改右）」與「可能的專有名詞（發音相近且上下文合理才改）」，刪「優先於不確定就不改」。

### F. 評估（不隨 App 出貨，`scripts/vocab-benchmark/`）
- 測試集 `tests/eval/vocab/`：cases-a（主控出題 128 句）＋cases-b（codex 獨立出題 128 句，主控未讀內容，當外部驗證）、learning-a／b 各 20 組。**改指示前 commit 定稿，之後不改。**舊版指示快照在 `scripts/vocab-benchmark/baseline/`。
- 模擬詞庫：每語言＝該語言全部題目的專有名詞（權重 1）＋10 個高權重常用詞（模擬現行權重偏差）。
- 計分（`scoring.mjs`＋單元測試）：**判定只用兩個原始計數**——專有名詞命中數（拉丁詞界、保留 `C++`／`C#` 符號）、誤改題數（詞庫詞在輸出出現次數多於標準答案）。字元錯誤率、改口字元錯誤率、必保留詞刪除率、數字格式、各語言／題組分組表**只印不判**。學習：配對召回率（分母＝標準答案配對數）、精確率（分母＝輸出配對數）、誤收數。
- 資料完整性防線（保留）：必要題單（cases-a／b）缺檔或與 `FROZEN.sha256` 不符即中止；非 200 或空輸出不算成績、兩邊 all 的題目 ID 必須完整；指示比較預設核對同輸入（辨識原文＋詞庫清單，快取命中也驗）；用量上限 3,000。
- **新版對照組必須呼叫 App 實際的訊息組裝函式**（`src/lib/enhancer.ts`／`src/i18n/prompts.ts`），不得在腳本自行組訊息；舊版對照組用凍結快照 `baseline/prompts-v016.ts` 並同樣走組裝函式。

## 驗收
1. 改動前跑基準，結果存 `tests/eval/vocab/results/`（不含金鑰、音檔）。
2. **換預設（指示）條件**（以「固定辨識＋同一新清單」比較；精簡、積極各判，兩模式都過才換、全有全無）：
   - 機械：整體專有名詞命中數（分母 281）新 ≥ 舊 + 3；整體誤改題數新 ≤ 舊；兩邊 all 題目 ID 完整、同輸入核對通過。
   - 語義檢視：乾淨 context 的唯讀審查者（非新指示作者；預設 codex，依語言拆顆）看全部 512 組盲測成對清單，只記四類重大錯（數值或單位變了、否定或對象反轉、改口留錯邊、實質內容被刪或被加），新舊對稱計數；校準＝混入 5 個構造反例，漏任一條換審查者重審，仍漏就在報告寫「語義檢視無效」交使用者。新版獨有重大錯題數 > 舊版獨有即不換（使用者拍板）。
   - 某語言明顯退步（命中數掉 ≥ 3，或該語言新版獨有重大錯多於舊版獨有）不自動裁決，列為「要你確認」。
3. **真人關**：換預設前請使用者本人錄約 15 句（人名、改口、數字、否定），新舊遮蔽由使用者判；每句有詞庫、無詞庫各跑一次（新安裝使用者走無詞庫路徑）；專有名詞與意思不得退步。只代表錄到的情境。
4. 學習：learning-a／b 中不該學的 0 筆被收；配對召回率 ≥ 80%、精確率 ≥ 90%（分母見 F）；升級後學到 3 次、重啟仍為 3（回填不覆蓋）。
5. 單元／整合測試：A0 裁切；對齊回推（純新增、截斷、同段兩詞、整詞回推、英文插字、日韓文、混合）；選詞（排序、候選規則、上限 20、無候選不附）；migration v9（新庫、v8 升級、缺欄恢復後升級、重跑）、刪詞觸發器、匯入計數；內建包標籤／自訂與編輯模式本體不變；新指示各語系組裝；評分器（兩條計數判定、缺資料不放行）。
6. 實機（Mac 開發版）：長日文詞詞庫錄音不再 400；5 句含詞庫詞看除錯日誌（提示位元組、AI 清單只帶相關詞）。
