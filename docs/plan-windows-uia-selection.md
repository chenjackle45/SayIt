# 計畫：Windows 讀選取改用 UIA、不再偷按複製（#79、#80；與右 Alt 遮罩聯合交付）（v0.14.2）

> 建立：2026-09-30 · 狀態：計劃閘第一輪 NO-GO（1 HIGH、5 MED，全收）→ 改版 → **第二輪 GO**（無新 finding，見文末）→ 可進入實作與試作 · 排程：v0.14.2，**發版等試作過關**（2026-09-30 使用者拍板）
> 來源：`docs/plan-windows-alt-menu-mask.md`「計劃閘第四輪」的裁定——UIA 選取讀取＋既有遮罩方案「分開實作、聯合驗收後交付」。本計畫只寫讀選取這一半；遮罩照原計畫方案 A，不在此重述。

## 要解決什麼

| 回報 | 已查證的事實 |
|---|---|
| #80：LINE／WeChat 按住 Alt 觸發先多一個 `C`，Shift 多反引號，PowerShell 出現 `^C`；**按下當下就出現**（obxyann 9/23 實測） | Windows 讀選取＝錄音開始時模擬 `Ctrl↓ C↓ C↑ Ctrl↑`、看剪貼簿（`text_field_reader.rs` Windows 分支 → `capture_selected_text_via_clipboard`），不抬起、不讀實體修飾鍵；按住模式在按下時就開始（`hotkey_listener.rs:460`） |
| #79：選取文字後按住 Alt／Shift 不進編輯模式，Ctrl 正常 | 同上，目標程式實收 `Alt+Ctrl+C` 之類；判準只看「剪貼簿非空」，不驗證是否真的來自反白 |
| （p.s.）無選取卻進了編輯模式 | 同一判準的假陽性來源尚未定位 |
| 停止時的第二次注入 | 停止流程在主探測未回覆時排程 250ms 後備、再送一次複製，Windows 也走得到（`useVoiceFlowStore.ts` 停止段） |

## 三問

1. **生產者**：每次在 Windows 開始錄音都注入一次複製；主探測慢一步時停止時再一次。頻率＝每次錄音。
2. **會 fire 嗎**：機制 1、2 直接移除注入本身，不依賴時序；是否真能讀到各程式的選取，要試作才知道（見代價）。
3. **砍什麼**：砍 Windows 上所有自動送 Ctrl+C 的路徑。理由獨立成立（污染輸入、且剪貼簿非空不等於有選取），不是因為遮罩讓它多餘。

## 五個機制（codex 第四輪消融表，**不得新增第六個**）

| # | 機制 | 定案內容 | 拿掉會壞的驗收 |
|---|---|---|---|
| 1 | **真選取讀取** | UIA TextPattern 取選取範圍；**恰好一段、且起點≠終點**才算選取，讀該範圍原文（不擴張、不讀整欄、不沿用游標附近摘錄的截斷）。零段、退化範圍、**多段（本版不支援，降級為無選取）**、不支援 TextPattern、錯誤、逾時一律回「無選取」。密碼欄位照既有規則排除。`trim()` 只沿用既有「空白不進編輯」政策，不代替範圍判定 | AC1、AC5 |
| 2 | **Windows 全面停用複製後備** | Windows 分支不再呼叫剪貼簿探測；前端停止段的 250ms 後備在 Windows 不排程 | AC2、AC5 |
| 3 | **有界等待、拒收晚到** | 後端總預算 **250ms，含工作執行緒初始化**；前端自發出本輪探測起 **500ms 總期限**（不是轉錄完才重新計時）。逾時、取消或模式已決定後，結果不得寫入狀態；等待返回後重查本輪身分。**只套 Windows**，macOS 的 AX 三態、600ms、停止後 250ms 後備不變 | AC3 |
| 4 | **Alt 放開前遮罩**（Hold／Toggle 皆涵蓋） | 照既有計畫方案 A | AC6 |
| 5 | **遮罩帶自家記號** | 照既有計畫 | AC4 |

**代價（明示）**：UIA 不支援的程式，這一版**不進編輯模式、不暗中退回複製**。若 LINE／WeChat 因此失去原本可用的編輯模式，不能以「沒有多字元」宣稱修好——試作要先回答這一題。

## 改動點

- `src-tauri/src/plugins/text_field_reader.rs`（Windows 分支）：
  - `read_selection_state` 改走 UIA 選取讀取，沿用既有 UIA 工作執行緒；所需介面已在 `Win32_UI_Accessibility` 內，**不改 `Cargo.toml`**
  - **移除啟動時的同步就緒等待**（現為無期限 `recv()`）：執行緒內初始化後再處理請求，初始化時間由既有的回覆等待期限涵蓋
  - 既有請求加「欄位／選取」種類；**選取不受欄位輪詢的「同時只跑一個」旗標拒絕**，仍走同一條有界佇列與期限。佇列滿或執行緒卡住時照失敗契約回無選取——不保證忙碌也成功
  - 不新增：重啟、重試、第二條執行緒、無限佇列、優先排程
- `src/stores/useVoiceFlowStore.ts`：Windows 不排程停止段後備；編輯模式判定依機制 3 的期限與拒晚到。macOS 路徑不變
- 遮罩：照 `docs/plan-windows-alt-menu-mask.md` 改動點；驗證「實際送出的資料」，抽出函式只是測試手段、不算必留機制
- `.claude/rules/windows.md`：「在錄音開始時就做剪貼簿探測」那條改寫成新做法

## 不做

強制送 Esc、模擬抬起／按回修飾鍵、複製重試、控制項焦點還原、多段選取編輯、#24 相關、任何 macOS 路徑、`capture_selected_text_via_clipboard` 本體（macOS 仍用）。

## 試作（W1＝B：安裝檔交 obxyann）

- **能證明什麼**：obxyann 手上的 v0.14.1（修前）對聯合版測試版（修後），在同一程式、模式、按鍵下驗真選取、無選取、開始／停止。這**只能證明聯合效果**：不能證明遮罩必要、也不能證明 Toggle 底線變化來自偷按複製——**根因維持「未證實」**，本版不宣稱遮罩必要性。聯合版失敗時才另出單項版定位；單項版不交付。
- **測試流程（定案）**：新增只能手動觸發的 CI 流程，只在 Windows 建置、上傳工作產物，**不建 tag、不建版本、不發布**。建置時以 CLI 設定覆寫合併：版號 `0.14.2-test.N`、**只產 NSIS**（MSI 不接受非數字的預發行識別）、`createUpdaterArtifacts: false`（不需要更新簽章金鑰）；**保留更新端點與公鑰**，正式版發布時才收得到。版號覆寫不提交進 repo。流程檔要先進 main 才能手動觸發。建置指令（第二輪審查確認 CLI 可行、未實際跑）：`pnpm tauri build --config '{"version":"0.14.2-test.1","bundle":{"targets":["nsis"],"createUpdaterArtifacts":false}}'`
- **版號順序**：`0.14.2-test.N` 比 v0.14.1 新（不會被拉回舊版）、比正式 v0.14.2 舊（正式版發布時會正常提示）。不能直接用 `0.14.2`——他會收不到正式版。
- 取檔要 GitHub 登入（obxyann 有帳號）；安裝檔未簽章，會出現與正式版相同的系統警告（#6）。
- **維護者工具測試**（按鍵送達順序、IME、AltGr、改鍵工具、Copilot 鍵）與 **#72 瀏覽器回歸**：沒有 Windows 設備、#72 回報者 9/11 後無回音——**記「未驗」**。
- **#70 原程式補測**：有測試版時才請 cruelforever 暫時改回單顆右 Alt 做修前修後；**沒補測前 AC6 視為未完成**。

## 驗收（codex 第四輪 AC1–6，依第一輪 finding 補齊）

| # | 項目 | 怎麼驗 |
|---|---|---|
| AC1 | 恰好一段非退化選取讀到原文；零段、退化範圍、多段、不支援、錯誤、逾時都回無選取；不以整欄或摘錄代替；**欄位讀取進行中時，選取仍能排入並在期限內完成**（前提：佇列有空位、兩者都能在預算內完成；佇列滿或執行緒卡住時，驗的是「準時回無選取」，不是保證成功） | Windows Rust 測試＋前端測試 |
| AC2 | Windows 開始、停止、主探測延遲與失敗，全程不呼叫複製後備 | 前端測試模擬慢回覆與停止競速（含主探測在原 250ms 期間回覆） |
| AC3 | 前端 500ms 總期限自發出探測起算；逾時、取消、下一輪、模式已決定後的晚到結果不改狀態；後端首次初始化也在 250ms 預算內；macOS 契約不變 | 前端可控 Promise／時間測試＋ Windows Rust 測試 |

| AC5 | 無多 `C`、反引號或 `^C`；真選取能編輯、無選取不誤判 | obxyann 原程式實測 |
